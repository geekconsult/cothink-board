# Implementation decisions

- Scope: a local native macOS board, a stdio MCP server, and JSON import/export. No network server or cloud sync.
- Data: a versioned Board contains notes, connections and visual groups. The store validates geometry and connection endpoints at its boundary.
- Concurrency: both processes use a file lock for transactions and revisions for optimistic conflict detection. Mutations are atomic board replacements, so an agent batch is one undo step.
- History: the local store retains snapshots for undo and redo and records actor and revision. A board export contains current state only.
- Access: a read-only MCP process is configured with an environment variable. Local process access is not an authentication system.
- Delivery: Swift Package Manager builds the application and server. A script assembles an unsigned app bundle for local use.
- Verification: `swift test` checks persistence, JSON round-trip, conflicts, undo, redo and validation. `scripts/test-mcp.py` exercises the server over real stdio with an isolated store. Native UI validation is reported separately.
- Architect evaluation: the requested cross-family design arena is unavailable with the current model access. This design is a single-team decision, not a cross-family verdict.

- Appearance: the supplied transparent mascot is bundled as the app icon and sidebar logo. The toolbar offers system, light, and dark appearances. Native Liquid Glass is used on supported macOS releases and system materials provide the fallback. Note text is chosen against its fill color for contrast.
- Project files: each board has a separate managed asset folder. The board stores a configurable folder path and asset metadata with relative file paths; notes refer to assets by ID. JSON export includes links and metadata, not file bytes. Moving the project folder through the app copies managed files and updates the base path.
- PDF export: three selectable HTML designs (Editorial, Studio, Minimal) share a visual board overview and readable note/relationship sections. A single long PDF page was rejected because it is hard to print; the renderer creates A4 pages at measured content boundaries and preserves image and text content. The same WebKit renderer serves the app preview/export and the local MCP helper. A visual review checked all three templates and multi-page output; sample PDFs were also checked for text, images and page size.
- Shapes: diagram shapes (rectangle, ellipse, diamond, line) are an optional Note variant field, not a new entity, so connections, groups, tree links and undo apply unchanged. A line is the diagonal of its bounding box, so a zero width or height is valid for line notes only.

- Workspace refinement: use a quiet, grouped canvas tool strip with an explicit active state, keeping the existing note colors and native materials. Place less frequent board actions, appearance, and export in one menu; keep zoom, inspector, and agent chat close at hand. A bright brainstorming treatment and a denser professional toolbar were considered but set aside in favor of the requested calm, canvas-first direction. The Home grid adapts to width and uses native buttons for keyboard access. Swift build and tests passed; native visual and interaction verification remains pending because screen capture failed in the current environment.

- Inspector visibility: automatic mode follows the selection. Explicit show and hide choices remain in effect until changed. Pointer-edge hover was rejected because it can interrupt canvas dragging. The inspector flushes pending changes before an explicit close. Board thumbnails summarize visible geometry; connection curves are simplified to straight lines. Agent chat groups secondary controls in Chat options and lets a user draft while a response is running. Native visual verification remains pending because the test app could not be captured in this session.

- Home redesign direction A: the Home grid gets a list chip row (one-click scope switching, replacing the scope dropdown shipped one commit earlier), a Recently opened row fed by a per-board last-opened timestamp stored as database metadata (no board revision bump, no undo noise), continuous scrolling instead of 12-per-page paging, and a Recent/Title sort plus a compact-grid density toggle. A left list-rail Home (Photos/Notion style) and a keyboard-first quick-open Home were built as full mockups and set aside: the rail duplicates the in-app sidebar at real list counts, and quick-open weakens visual browsing; both remain future add-ons on the chip-row base. The three-way comparison page (.scratch/home-redesign/exploration.html) cleared a dual design-review + detector gate before the owner picked.

- Home supports one pinned list per workspace. The account syncs its list ID so switching pins takes one edit. Home previews up to four boards and links to the complete list to keep All boards within reach. Native Home interactions and authenticated Mac-to-browser and browser-to-Mac pin changes were verified with a disposable workspace.
